BPSC AI Platform

Document 12 — Final Product Roadmap & Phased Implementation Plan

Purpose: Convert Documents 01–11 into one practical execution roadmap for building, refactoring, launching, and scaling the BPSC AI personal mentor platform.

Audience: Product owner, engineering team, AI/RAG engineers, DevOps, QA, content experts, business team, and Claude Code.

Status: Final implementation blueprint

1. Executive Summary

The BPSC AI platform should be built as an AI personal mentor, not simply an answer-checking bot. The core learning loop is QUESTION → HANDWRITTEN ANSWER → OCR/VISION → RAG EVIDENCE → EXAMINER → FEEDBACK → LEARNING PROFILE → NEXT QUESTION.

The recommended strategy is incremental. Keep the existing Node.js/Telegram product working while introducing modular boundaries around AI, RAG, evaluation, storage, jobs, analytics, and domain logic. Do not attempt a large rewrite before the critical student journey is covered by tests and observability.

Phase 0: Baseline, audit, safety, and test foundation.

Phase 1: Production-grade MVP core.

Phase 2: AI evaluation and personalized mentor.

Phase 3: Beta, analytics, monetization, and quality optimization.

Phase 4: Web/Android expansion and scale.

Phase 5: Advanced learning intelligence and defensible data moat.

2. Final Product Vision

Build the most useful AI-assisted BPSC answer-writing mentor for Hindi-medium aspirants by combining exam-pattern knowledge, NCERT-grounded evidence, Bihar-specific context, current affairs, handwritten-answer understanding, examiner-style evaluation, and longitudinal personalization.

Student gets the right question, not a random question.

Student can write naturally by hand.

AI evaluates against an explicit blueprint and rubric.

Feedback explains what to improve and how.

Repeated attempts create a learning profile.

Future questions adapt to demonstrated strengths and weaknesses.

Every important AI result is traceable to prompt/model/source versions.

4. Architecture Target State

Target architecture remains a modular monolith initially, with separate processes for API, workers, scheduler, and admin/web where useful. High-load components can later be extracted into services.

Node.js + TypeScript application layer.

PostgreSQL as system of record.

pgvector for initial vector retrieval.

Redis + BullMQ for asynchronous work.

S3-compatible object storage for handwritten images.

AI Gateway as the only external model-provider boundary.

RAG service/module for evidence retrieval and provenance.

Telegram as first client; Web and Android as later clients.

Centralized logs, metrics, traces, AI usage, and quality telemetry.

7. Phase 1 — Explicit Non-Goals

Do not build a full social network.

Do not build dozens of microservices.

Do not build a complex Android app before the core loop is validated.

Do not ingest the entire internet.

Do not generate expensive full model answers for every attempt.

Do not make AI scoring an official-exam claim.

Do not optimize advanced personalization before collecting reliable learning signals.

15. Migration Strategy From Current Node.js Application

The migration must be incremental and reversible.

Freeze a known-good baseline and tag it.

Add tests around current behavior before moving logic.

Introduce TypeScript where appropriate without forcing a full rewrite.

Create domain/application modules around existing Telegram handlers.

Move AI calls behind AI Gateway adapters.

Move heavy operations into BullMQ workers.

Introduce PostgreSQL repositories and explicit transactions.

Add object storage abstraction for images.

Introduce RAG as an isolated module.

Introduce Evaluation Blueprint storage.

Route existing flows through the new modules.

Remove duplicated legacy code only after equivalent tests pass.

18. AI Model Strategy

Keep all model calls behind AI Gateway.

Use task-specific model routing rather than one model for everything.

Use stronger models for difficult evaluation or quality-critical cases.

Use lower-cost models for classification, tagging, simple transformations, and some retrieval tasks when benchmarked.

Cache stable outputs where safe.

Use asynchronous processing for non-interactive expensive operations.

Track provider/model performance continuously.

Maintain fallback providers/models for critical operations where practical.

21. Content Governance

Every source has owner, type, authority tier, version, and ingestion status.

PYQs must be verified before entering the trusted corpus.

Current-affairs sources must carry publication/effective dates.

Conflicting information must be flagged rather than silently merged.

Deleted or superseded sources remain traceable in historical AI traces.

Content reviewers can disable problematic chunks without code deployment.

31. Product Moat

The defensible advantage is not the underlying LLM. It is the combination of curated BPSC knowledge, verified PYQ lineage, evaluation blueprints, expert-calibrated rubrics, handwritten-answer data, longitudinal learning signals, and adaptive practice.

Question lineage becomes proprietary structured knowledge.

Evaluation traces become a benchmark for answer-writing quality.

Student histories enable personalization.

Human-vs-AI benchmark data improves reliability.

Content governance improves trust.

Repeated attempts create a learning dataset that generic AI assistants do not naturally possess.

Product decisions are driven by learning outcomes and retention, not vanity usage.

36. Final Product Principle

Build the smallest system that can reliably produce a complete learning loop, measure whether it improves students, and then make that loop smarter. Do not start by building a giant AI platform. Start by building a trustworthy BPSC mentor.

The strategic sequence is: TRUST → RELIABILITY → LEARNING VALUE → PERSONALIZATION → RETENTION → MONETIZATION → SCALE.

Documents 01–12 together form the implementation baseline. Claude Code should use them as the source of truth, while treating explicit product-owner decisions and verified production constraints as higher-priority inputs when they evolve.
